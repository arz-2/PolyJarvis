PHAL is confidence=medium and IS in polymer_rules.json with class-specific temperatures (T_equil=700, anneal=780, 5 cycles; Tg sweep 100-550 K @ 20 K, rates [25,50,100]). Build a **reasoned** plan (medium forces it). Members: PVDF (*CC(F)(F)*, Tg 233), PTFE (*C(F)(F)C(F)(F)*-ish, Tg controversial ~160), PCTFE (Tg 325).

**Member pin by SMILES:** `*CC(F)(F)*` = PVDF (CH2-CF2 repeat) — exp Tg 233 K, density 1.75-1.78 g/cm3 @283K (Byutner & Smith 2000, doi 10.1021/ma9918295). Pin explicitly in D-04 even though for PVDF the dict-median helper (`_exp_tg_scalar`, used only for T_workflow_K/regime) happens to coincide with the pinned value — note that coincidence explicitly for the critic, don't rely on it (PEEK/PEKK median-pick precedent shows it fails in general).

**Regime wrinkle unique to this class — READ CAREFULLY:** PVDF's exp Tg (233 K) is BELOW 300 K, so the scaffold sets `T_workflow_K=300.0` / `glassy_hint=False` (nominally rubbery). But the class's OWN notes say OPLS-AA/MD systematically overpredicts Tg by 80-120 K for this class (expected MD Tg ~310-350 K) — i.e. the measured Tg is expected to land ABOVE 300 K. Since `tg` is virtually always requested, `is_glassy` is correctly derived from the MEASURED Tg at runtime (property_method policy), so the mechanical regime can flip mid-run. **This is NOT automatically handled**: `bm_pressures_atm` is a single `decided_params` value threaded verbatim into the murnaghan prompt regardless of `is_glassy` (checked `gen_prompt.py:murnaghan_prompt` + `murnaghan-worker.md` this run — the `glassy_assertion` only forces submission on a glassy cell, it does NOT swap in a different pressure ladder). Plan a REGIME-ROBUST pressure ladder (an all-compression sweep works reasonably for either phase; see BM_ANALYSIS.md's B0'-out-of-range WARNING-not-FAIL band as the safety net) and say so explicitly in D-07 rather than writing prose implying an automatic "flip to compression-biased pressures" — nothing executes that flip.

**Class-rules gap (worth fixing upstream):** PHAL carries `bm_pressures_atm: null` and `exp_K_GPa: null` at the class level (checked `jq '.classes.PHAL'`). Unlike PHYC/PDIE (rubbery, which carry `[1,500,1000,2000,5000]` + a PVT/Tait-sourced `exp_K_GPa`), a rubbery-hinted PHAL run with no override would fall through `make_deterministic_plan.py:build_planned_stages`'s `elif bm_pressures_atm: ... else: rubbery without pressures -> fluctuation path, no murnaghan submit stage` — silently downgrading the primary method (property_method policy says Murnaghan EOS-sweep is primary even for rubbery). **Fix at plan time**: add `bm_pressures_atm=[1,500,1000,2000,5000]` (PHYC/PDIE convention) into `decided_params` AND add an explicit `murnaghan` stage (with `deform` fallback) to `planned_stages` — do not let the class-rules gap silently choose fluctuation-only. No `exp_K_GPa` was found anywhere (rules, grounding) for PVDF — leave it unset, flag for exp-lookup-worker, and expect run-summary to report K ungraded rather than force a target.

**FF (D-01) — literature-grounding correction pattern:** this run's grounding worker found the class's own `ff_justification_doi` (10.1021/ma9918295, Byutner & Smith 2000) is actually a bespoke non-OPLS PVDF force field (Buckingham exp-6), not an OPLS-AA validation — it only corroborates the density/Tg experimental TARGETS. The real OPLS-AA lineage is Watkins & Jorgensen 2001 (10.1021/jp004071w, perfluoroalkane CF2/CF3 params) — a RELATED-class validation (all-CF2 PTFE-like, not PVDF's mixed CF2-CH2), which is exactly the `evidence_levels.medium` definition in decision_policy.json. **How to apply a grounding-invalidated ff_justification_doi generally:** don't just drop the citation — (1) keep citing it for whatever it DOES verifiably support (here: density/Tg targets), (2) find/promote the citation that actually supports the FF choice itself if grounding surfaced one, (3) keep D-01 confidence at the level the surviving evidence supports (medium here, not downgraded further, since parameter_coverage/builder-constraint + a genuine related-class paper is still a real medium-tier basis), (4) make the citation-chain weakness the DOMINANT uncertainty (`ff_transferability`) with `reduction_probe: fast_density_screen` (not another `literature_anchor` round — that probe already ran this run and hit ACS/ChemRxiv paywalls; a density screen is a NEW empirical check the citation gap can't answer).

**D-06 Tg ladder:** kept class default `[25,50,100]` K/ns (0.602-decade span) rather than pre-widening to PVNL's 1.2-dec fix — PHYC/PDIE (rubbery, TraPPE) use the identical 0.602-dec ratio (`[10,25,40]`) as their own unflagged class default, so 0.602 dec looks like an accepted campaign convention, not a PVDF-specific known-defect. Per [[feedback-dont-assert-prior-run-results-unchecked]], don't assume the PVC slope-gate failure generalizes without PVDF-specific evidence — record `tg_rate_span_slope_gate` as non-dominant, `reduction_probe: none` (defer to the orchestrator's documented recovery ladder if it actually fails).

**D-08 hardware:** family=opls. Cell ~ dp60 x nchain10 x 6 atoms/monomer (all-atom C2H2F2, hand-counted — rdkit unavailable in the planner bash env, same gap as psfo_reasoned_plan) = ~3,600 atoms, within [0.5x,2x] of the 3,220-atom OPLS benchmark cell. Adopt `by_forcefield.opls` default (kokkos/mpi=1/1GPU); DON'T write hardware into decided_params (matches default). Live host THIS run was 4x RTX 6000/18 phys cores (nvidia-smi+nproc), matching `hardware_policy.host` but NOT `directional_probe.measured_on` (A800/32-core) — set D-08 `confidence:low` + `hardware_optimum` uncertainty + `reduction_probe: hardware_benchmark`, matching the pstr/psfo pattern for a host-mismatched, unbenchmarked box.
